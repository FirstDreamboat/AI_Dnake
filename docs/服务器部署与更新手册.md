## 二、从零部署流程（新虚拟机时照此执行）

### 1. 创建虚拟机（参考研发部《智慧病房管理平台0-1搭建环境.docx》第一~四节）

1. PVE 建虚拟机：镜像 CentOS、磁盘 100G（本次实际 50G，够用）、CPU **4核、类型 host**、内存 8192MB、开机自启
2. 装 CentOS 7.8，配置静态 IPv4、DNS 8.8.8.8，root 密码自设
3. 本地 SSH 连通（MobaXterm / FinalShell / `ssh root@IP` 均可）

### 2. 环境体检（每台新机器必做）

```bash
cat /etc/centos-release && nproc && free -h && df -h /
curl -sv --connect-timeout 8 https://api.deepseek.com 2>&1 | grep -E "Connected|SSL" | head -3
curl -sv --connect-timeout 8 https://api.siliconflow.cn 2>&1 | grep -E "Connected|SSL" | head -3
```

两个 API 域名必须能建立 TLS 连接（响应 404/401 都算通）。

### 3. 换 yum 源（CentOS 7 已 EOL，必做）

```bash
curl -o /etc/yum.repos.d/CentOS-Base.repo https://mirrors.aliyun.com/repo/Centos-7.repo
yum clean all && yum makecache
```

> `mirrors.aliyuncs.com` 超时是正常现象（那是阿里云内网域名），yum 会自动切公网镜像，最终出现"元数据缓存已建立"即成功。

### 4. 安装 Docker + Git

```bash
yum install -y yum-utils git
yum-config-manager --add-repo https://mirrors.aliyun.com/docker-ce/linux/centos/docker-ce.repo
yum install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
systemctl enable --now docker
docker --version && docker compose version
```

### 5. 配置 Docker 镜像加速（Docker Hub 被墙，必做）

```bash
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://docker.1ms.run",
    "https://docker.1panel.live",
    "https://hub.rat.dev"
  ]
}
EOF
systemctl daemon-reload && systemctl restart docker
docker info | grep -A 6 "Registry Mirrors"
```

### 6. 防火墙放行 8080

```bash
firewall-cmd --permanent --add-port=8080/tcp && firewall-cmd --reload
```

### 7. 拉取代码（GitHub 直连不通，走加速代理）

```bash
cd /opt
git clone --depth=1 https://ghfast.top/https://github.com/FirstDreamboat/AI_Dnake.git
cd AI_Dnake
git remote set-url origin https://ghfast.top/https://github.com/FirstDreamboat/AI_Dnake.git
```

### 8. 配置 backend/.env（仓库不含此文件，必须手动放置）

- 方式 A：MobaXterm 文件面板把本地 `backend/.env` 拖到 `/opt/AI_Dnake/backend/.env`
- 方式 B：`cp .env.example .env` 后手工填

必填项：`EMBED_API_KEY`、`VISION_API_KEY`、`DEEPSEEK_API_KEY`（三个硅基流动/DeepSeek 的 Key）、`SECRET_KEY`。
建议改：`DEBUG=false`、`APP_ENV=production`。
**不用配 `DATABASE_URL`**——compose 用环境变量 `mysql+pymysql://testgen:...@mysql:3306/...` 覆盖它。

### 9. 构建启动

```bash
cd /opt/AI_Dnake
docker compose up -d --build      # 首次 5~15 分钟
docker compose ps                  # 三容器 Up / healthy
```

### 10. 验证

```bash
curl -s -o /dev/null -w "前端:%{http_code}\n" http://localhost:8080          # 200
curl -s http://localhost:8080/api/v1/system/health                           # {"detail":"Not authenticated"} 即链路通
```

浏览器打开 `http://192.168.60.190:8080`：登录（验证码清晰）→ 建项目 → 上传文档 → 解析 → 生成用例 → 导出 Word/PPT/PDF。

## 三、日常更新流程（代码改动后）

```bash
cd /opt/AI_Dnake
git pull                              # 经 ghfast 代理拉最新代码
docker compose up -d --build          # 重建镜像并滚动替换容器
docker compose ps                     # 确认三容器 Up / healthy
```

要点：

- **只改后端代码**：`docker compose up -d --build backend`
- **只改前端**：`docker compose up -d --build frontend`
- **改了 requirements.txt / package.json**：正常 `--build` 会自动装新依赖
- **数据库结构变更**：需确认建表/迁移逻辑，属重大变更，提前演练
- 停机窗口：重建期间 1~3 分钟不可访问，**答辩前更新要提前一天做**
- 数据安全：MySQL/上传/向量库都在卷里，重建容器**不会丢**；但更新前建议先备份（见下）

### 更新前备份（建议每次执行）

```bash
# 数据库快照（放到 /opt/backup，按日期命名）
mkdir -p /opt/backup
docker exec testgen-mysql mysqldump -uroot -ptestgen_root_1234 --single-transaction ai_testcase \
  > /opt/backup/ai_testcase_$(date +%Y%m%d_%H%M).sql
```

### 更新失败回滚

```bash
git log --oneline -5                  # 找上一个正常版本的 commit
git checkout <commit>                 # 切回旧版本
docker compose up -d --build          # 重建
git checkout master                   # 确认恢复后切回主分支
# 数据库回滚：docker exec -i testgen-mysql mysql -uroot -ptestgen_root_1234 ai_testcase < /opt/backup/xxx.sql
```

### 整机快照（终极兜底，找 IT 操作）

PVE 上右键虚拟机 → 快照 → 拍摄快照。当前已有"代码最新 + 本地数据全量"快照，任何事故 5 分钟整机恢复。

## 四、数据迁移记录（本地 → 服务器，2026-10-20 已完成）

1. 本地导出：`mysqldump -h127.0.0.1 -P3306 -uroot -p*** --single-transaction ai_testcase > ai_testcase.sql`（6.1 MB，16 表）
2. 打包数据：`tar -czf data.tgz -C backend/data uploads vector`（192.7 MB）
3. MobaXterm 传入服务器 `/opt/migrate/`
4. 导入：
   ```bash
   docker exec -i testgen-mysql mysql -uroot -ptestgen_root_1234 ai_testcase < ai_testcase.sql
   tar xzf data.tgz
   docker cp uploads/. testgen-backend:/app/uploads/
   docker cp vector/. testgen-backend:/app/data/vector
   docker compose restart backend
   ```
5. 验证：`SELECT (SELECT COUNT(*) FROM project) p, (SELECT COUNT(*) FROM test_case) c, (SELECT COUNT(*) FROM knowledge_doc) k;` → 4 / 5032 / 3 ✓

> 注意：导入是覆盖式的，服务器新注册的账号会被本地数据替换。以后如需反向同步（服务器 → 本地），用同样的 mysqldump 反向操作。

## 五、排障记录（真实踩坑，复用时按编号查）

| # | 现象 | 根因 | 解法 | 状态 |
|---|---|---|---|---|
| 1 | MySQL 容器 `Fatal glibc error: CPU does not support x86-64-v2` | PVE 默认 CPU 类型 kvm64 缺 SSE4.2/POPCNT | PVE 虚拟机硬件 → 处理器 → 类型改 **host**（或 `qm set <vmid> -cpu host`） | ✅ 已修复 |
| 2 | nginx 容器崩溃重启，`pwrite() "/run/nginx.pid" failed (Operation not permitted)` | 最新 nginx:alpine（1.31/Alpine 3.22）不兼容内核 3.10 | Dockerfile 钉死 `FROM nginx:1.26-alpine` | ✅ 已修复（commit 215c9f3） |
| 3 | 前端构建失败，vue-tsc 报 6 个 TS 错误 | 生产构建才做类型检查，开发模式暴露不了 | 修 `editForm.module` 缺声明、`selectedIdsArr.value` 漏解包、删未用变量、`String(k)` 替代类型断言 | ✅ 已修复（eebd24d） |
| 4 | `git clone` 报 `RPC failed result=35` / 443 超时 | GitHub 国内连接不稳 | `git clone --depth=1` + ghfast.top 加速代理；remote 永久改为代理地址 | ✅ 已解决 |
| 5 | `docker compose up` 拉 mysql 镜像超时 | Docker Hub 被墙 | `/etc/docker/daemon.json` 配 4 个国内加速源 | ✅ 已解决 |
| 6 | 登录验证码字符极小 | 容器内无 arial.ttf，PIL 回退 11px 位图字体 | 字体优先级列表（DejaVu → Arial），画布 160×48、字号 34 | ✅ 已修复（b0aa876） |
| 7 | `yum makecache` 间歇报 `mirrors.aliyuncs.com` Timeout | 阿里云内网域名，非阿里云机器不可达 | 无需处理，自动切公网镜像 | ℹ️ 正常现象 |
| 8 | `/api/health` 返回 404 | 路径不对 | 健康检查真实路径为 `/api/v1/system/health`，未登录返回 401 即正常 | ℹ️ 认知纠正 |

**教训**：CentOS 7（内核 3.10）+ 最新容器镜像 = 持续的兼容性风险。所有基础镜像版本已钉死，**今后升级镜像版本前务必先确认内核兼容性**。长期方案：迁移到 Ubuntu 22.04 虚拟机可根治此类问题。
